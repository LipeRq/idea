## 1. PoCの目的

御社の実際の見積データで、見積アシストが御社の業務で使えるか、費用に見合う効果がありそうかを確かめ、本導入するかどうかを判断する材料をそろえます。

PoCで確かめることは次の3つです。

| # | 確かめること | 主な指標(4章) |
|---|---|---|
| 1 | 御社の図面・引き合いメールを、どのくらい正確に読み取れるか。不足している情報を見つけられるか | 読み取りの正解率、自信のある誤り、確認事項の検出率 |
| 2 | 単価表と計算ルールで、御社の過去の見積額を再現できるか。似た過去案件を探せるか | 計算の再現度、工数案の差、類似検索の的中率 |
| 3 | 見積1件あたりの作業時間がどのくらい変わりそうか。費用に見合うか | 作業時間、処理時間とAIの費用、担当者の評価 |

**PoCでやらないこと:** 本番の運用、お客様への実際の送信、Salesforceの本番環境への登録、過去データ全件の取込、生産管理システムとの連携。

## 2. 期間と日程

6週間の場合の例です。4週間の場合は、3週目と4週目をまとめ、5週目を省きます。

| 週 | 内容 | 御社にお願いすること | 当社が行うこと |
|---|---|---|---|
| 事前(開始の2〜4週間前から) | 秘密保持契約、NDAの確認、ベースライン計測の開始(5章)、データの準備 | NDAの確認、記録シートへの記入、データの用意 | 記録シートの用意、データ受け渡し方法の準備 |
| 1週目 | キックオフ(目的・範囲・**合格基準**の確定)、聞き取り(単価の考え方、2時間程度)、データの受け取り | キックオフと聞き取りへのご出席 | 進め方の説明、聞き取り |
| 2週目 | PoC用の単価表・計算ルールの設定、データの取込、正解データの作成 | 単価表と正解データの確認 | 設定と取込、正解データの下書き |
| 3週目 | 評価1:読み取り・確認事項・類似検索・計算の再現を一括で評価 | (定例のみ) | 評価の実行と集計 |
| 4週目 | 評価2:見積担当者が実際に使い、作業時間を計る(10件程度) | 見積担当者による試用 | 操作説明、記録 |
| 5週目 | 追加の評価・改善(単価表の調整など)、結果の集計 | (定例のみ) | 改善と再評価、報告書の作成 |
| 6週目 | 報告会と本導入の判断(10章) | 決裁者のご出席 | 報告 |

定例:毎週【○曜日】30分(進み具合の確認と、聞き取りの補足)

## 3. 対象データ(30〜50件)

### 3.1 選び方

直近【1〜2年】の見積から、図面PDFと見積額がそろっているものを30〜50件選びます。結果が偏らないよう、次の種類を混ぜます。

| 種類 | 件数の目安 | 確かめたいこと |
|---|---|---|
| リピート品・図面の改訂品 | 10〜15件 | 同じ図番や旧版を探せるか、過去の実績を活かせるか |
| 新規品 | 10〜15件 | 読み取りの正確さ、似た過去案件を探せるか |
| 情報が不足していた引き合い | 5〜10件 | 確認事項を見つけられるか |
| 短納期・特殊な工程(熱処理・研削など) | 5〜10件 | 特急料金や外注の扱い、警告 |

- 受注した案件と失注した案件の両方を含めます。
- 実績工数・実績原価が分かる案件は、できるだけ含めます(見積と実績の差を見るため)。
- **対象外:** 装置一式・組立品、3Dデータだけの案件、NDAで外部のクラウド・AIの利用が認められていないお客様の図面。

### 3.2 1件ごとにいただくもの

| 資料 | 必須/任意 | 使い道 |
|---|---|---|
| 図面PDF | 必須 | 読み取りの評価 |
| 引き合いメールの本文(なければ依頼内容のメモ) | 必須 | 読み取りの評価(メールがない場合は当社が依頼内容を文章にします) |
| 実際に出した見積書(数量・単価・金額) | 必須 | 計算の再現度、工数案の差 |
| 見積の明細・工数のメモ | あれば | 計算の再現度、単価表の確認 |
| 当時お客様に問い合わせた事項 | あれば | 確認事項の正解 |
| 受注・失注と、その理由 | あれば | 類似案件の表示 |
| 実績工数・実績原価 | あれば | 見積と実績の差 |

### 3.3 類似検索の検索先

- 見積台帳(Excelなど)があれば、評価用の30〜50件とは別に全件をいただき、類似検索の検索先にします。
- 台帳がない場合は、評価用の30〜50件の中で、1件ずつ「その案件以外」から探す方法で評価します。

### 3.4 正解データの作り方

御社のご負担を減らすため、当社が下書きを作り、御社には確認だけをお願いします。

| 正解データ | 作り方 |
|---|---|
| 読み取りの正解 | 図面と見積書から、当社が項目ごとの正解表を作り、見積担当者が確認する |
| 確認事項の正解 | 当時実際に問い合わせた事項に、見積担当者が「本来は確認すべきだった」とする事項を加える |
| 類似案件の正解 | 評価用のうち【15〜20件】について、見積担当者に「この見積を作るときに参考にする過去案件」を1〜3件挙げていただく |

## 4. 評価指標と測り方

| # | 指標 | 定義・計算式 | 測り方 |
|---|---|---|---|
| 1 | 読み取りの正解率(項目別) | 正しく読み取れた件数 ÷ 評価件数。項目は図番・版・材質・数量・外形寸法・最小公差・表面処理・熱処理・希望納期・検査書類 | 正解データと照合する(当社がPoC用に用意する評価の仕組みを使う) |
| 2 | 自信のある誤り | 確からしさが「高」なのに誤っていた項目の数 | 同上。**人の確認が形だけにならないよう、最も重視する指標** |
| 3 | 確認事項の検出率 | AIが挙げた確認事項のうち正解に含まれる数 ÷ 正解の確認事項の数。あわせて「不要な確認事項」の数も数える | 正解データと照合する |
| 4 | 類似検索の的中率 | 見積担当者が挙げた参考案件が上位5件に入った件数 ÷ 対象件数 | 3.4の正解と照合する |
| 5 | 計算の再現度 | 実際の見積の工数を入力して計算した額と、実際の見積額の差(差の絶対値 ÷ 実際の見積額)。中央値と、【±○%】以内に入った割合 | 単価表とルールが御社の考え方を表せているかを確かめる |
| 6 | 工数案の差 | AIの工数案で計算した額と、実際の見積額の差(中央値とばらつき) | 同上 |
| 7 | 作業時間 | 見積アシストを使ったときの1件あたりの作業時間(担当者別)と、ベースラインの比較 | 見積担当者が10件程度を実際に処理し、画面の記録と時刻のメモで測る |
| 8 | 処理時間とAIの費用 | 1件あたりの処理時間、AIのトークン数(処理量)、概算費用 | 見積アシストの記録 |
| 9 | 担当者の評価 | 「使いたいか」「根拠が分かりやすいか」「信頼できるか」の5段階評価と自由記述 | 試用後のアンケート |

**作業時間の測り方の注意:**
- 過去案件の見積をやり直す形になるため、担当者が答えを覚えている案件では時間が短く出ます。試用には、担当者が詳しく覚えていない案件を選びます。
- より実際に近い数字が必要な場合は、PoC期間中に届いた新しい引き合いで「並行運用」を行います(いつもどおり見積を作り、別に見積アシストでも作って比べる。お客様への送信はいつもの方法だけ)。この場合も、そのお客様とのNDAの確認が必要です【実施する/しない】。

## 5. ベースライン計測の方法

導入前の今の値を測り、PoCと導入後の比較の基準にします。

| 項目 | 内容 |
|---|---|
| 期間 | 2〜4週間。PoC開始前から始めます。難しい場合は1週目から並行し、過去の記録で補います |
| 対象 | 期間中に届いたすべての引き合い(【対象の品目に限る】) |
| 記録の方法 | 下の記録シートに1件1行で記入します。時刻は5分単位で構いません |
| 回答日数 | 受付日時と回答日時から営業日数を計算し、中央値を使います |
| 過去の記録での補い方 | Salesforceの商談の作成日と見積の送付日、メールの送受信日時、見積台帳の日付 |

**記録シート(例)**

| 受付日時 | お客様 | 品名・図番 | 種類(新規/リピート/改訂) | 図面枚数 | 見積担当 | 作業時間:営業・事務(分) | 作業時間:見積担当(分) | 回答日時 | お客様への問い合わせ | 受注/失注 | メモ |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 【】 | 【】 | 【】 | 【】 | 【】 | 【】 | 【】 | 【】 | 【】 | 【あり/なし】 | 【】 | 【】 |

- 作業時間は「その見積のために手を動かした時間」の合計です。お客様の返事待ちなどの待ち時間は含めません(待ち時間は回答日数に表れます)。
- 実測できなかった値は「推定」と書いて区別します。
- 記録を始めると、普段より急いで作業するなど、行動が変わることがあります。2週間以上続けると普段の値に近づきます。

## 6. 合格基準の決め方

### 6.1 原則

- **結果を見る前に、キックオフで御社と一緒に決めます。** 結果を見てから基準を動かすと、判断がぶれるためです。
- 指標ごとに「最低ライン(下回れば本導入しない)」と「目標」の2段階にします。
- 作業時間の基準は、費用対効果から逆算します。

### 6.2 作業時間の基準の逆算

```
必要な削減時間[時間/件] = 月額[円] ÷ 時間単価[円/時間] ÷ 月の引き合い件数[件]
```

例:月額7.5万円、時間単価3,000円、月60件の場合
75,000 ÷ 3,000 ÷ 60 = 約0.42時間 = **約25分/件**。
作業時間の削減が1件あたり25分を超えないと、月額の分も取り戻せない計算になります。初期費用の回収まで考える場合は、回収期間[か月] =(PoC費用 + 初期導入費)÷(月の削減額 − 月額)で確認します。

### 6.3 合格基準の記入表

| 指標 | 最低ライン | 目標 | 決めた理由 |
|---|---|---|---|
| 主要項目(材質・数量・図番・版)の読み取り正解率 | 【】 | 【】 | 【】 |
| 自信のある誤り | 【○件以下】 | 【】 | 【】 |
| 確認事項の検出率 | 【】 | 【】 | 【】 |
| 類似検索の的中率(上位5件) | 【】 | 【】 | 【】 |
| 計算の再現度(【±○%】以内に入った割合) | 【】 | 【】 | 【】 |
| 1件あたりの作業時間の削減 | 【6.2で逆算した値】 | 【】 | 【】 |
| 見積担当者の評価(「使いたい」の5段階) | 【】 | 【】 | 【】 |

一部の指標だけが基準に届かない場合は、対象を絞れば届くか(例:スキャン図面を外す、旋削品だけにする)も確認し、範囲を絞った導入を検討します(10章の選択肢B)。

## 9. 機密情報の扱い

| 項目 | 扱い |
|---|---|
| 契約 | PoCの開始前に、当社と御社で秘密保持契約を結びます |
| お客様(発注者)とのNDA | 御社がお客様から受け取った図面は、そのお客様とのNDAで外部のクラウド・AIの利用が認められているかを確認します。認められていない、または判断できない図面はPoCの対象から外します |
| 必要なものだけ受け取る | PoCに必要な資料だけをいただきます。評価に影響しない情報(お客様の担当者名など)は伏せていただいて構いません |
| 受け渡し | 【例:パスワード付きのファイル共有サービス/御社指定のクラウドストレージ】を使い、メールへの添付は避けます |
| 保存場所 | 当社が管理する【保存先(例:国内リージョンのクラウドストレージ)】に保存し、アクセスできるのはPoCの担当者だけにします |
| AIでの処理 | 図面と本文は、AI(Anthropic社のClaude)への依頼の中で送り、AI側のファイル保管機能は使いません。同社の商用APIで送ったデータは、標準ではAIの学習に使われないと公表されています。AIの会社側での保存期間は同社の規約に従います(PoCの開始前に最新の規約で確認し、書面でお伝えします) |
| 国内での処理 | 国内で処理する必要がある場合は、Amazon Bedrock の国内(東京・大阪)の処理経路を使う構成を検討します(AIの料金は約10%高くなります)。PoCで使えるかは【要確認】 |
| 記録(ログ) | 処理時間・処理量・エラーの種類だけを記録し、図面の内容・メール本文・金額・お客様の名前は記録しません |
| 他の用途に使わない | 御社のデータを、他のお客様の検索や評価に使いません |
| PoC終了後 | 本導入しない場合は、受け取ったデータと作ったデータを【○日以内】に削除し、削除したことを書面でご報告します。本導入する場合は、そのまま引き継ぎます |
| 万一のとき | 漏えいの疑いがあれば【○時間以内】にご連絡し、対応を協議します |

## 10. PoC後の判断の進め方

### 10.1 報告会でお伝えすること

1. 指標ごとの結果と、合格基準との比較
2. うまくいった項目・いかなかった項目と、その理由
3. 作業時間の変化と、実測値で更新した費用対効果の試算
4. 本導入する場合の範囲・費用・スケジュールの案
5. リスクと対策

報告書は報告会の【○営業日前】にお送りします。

### 10.2 判断の選択肢

| 選択肢 | 目安 | 次の動き |
|---|---|---|
| A. 本導入 | 最低ラインをすべて満たす | 初期導入の契約、スケジュールの確定 |
| B. 範囲を絞って導入 | 一部の品目・図面の種類でだけ満たす | 対象を絞った見積・計画をお出しする |
| C. 追加の検証 | 件数が足りないなど、判断材料が不足 | 期間・費用・確かめることを決めて延長 |
| D. 見送り | 最低ラインを満たさない | データを削除し、見送りの理由を記録する |

- 判断の期限:報告会から【2週間以内】
- 判断する方:【代表取締役 ○○様】
- PoC費用の扱い:【例:本導入の場合は、初期導入費から○万円を差し引く】
