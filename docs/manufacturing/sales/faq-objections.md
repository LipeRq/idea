## 1. AIの正確さ

<a id="q1"></a>
### Q1 AIが図面を読み間違えたらどうなるのか

**ひとことで:** AIは読み間違えることがあります。そのため、読み取った値には「確からしさ」と「図面のどこに書いてあったか」を添え、怪しい項目は目立たせます。未確認の項目が残っていると、確認のチェックを入れないと承認できず、未確認のまま進めたことが記録に残る仕組みです。

**補足**
- 読み取った項目ごとに、確からしさ(高・中・低)と根拠(図面のファイル名・ページ・位置・原文の引用、メールのどの文か)を表示します。
- 確からしさが低い、根拠がない、単価表と合わない値は「要確認」、読み取れなかった必須項目は「不足」と表示します。これらが残ったまま承認しようとすると、確認のチェックを求め、その記録を残します。
- 金額はAIの出力から作らず、プログラムが単価表で計算します(Q2)。過去の実績から大きく外れた金額や、更新日の古い単価表には警告を出します。
- 見積の送信は人が行います。自動送信はしません。

**根拠:** use-cases.md 5.9(誤った見積への対策)、quote-assist-design.md 3章

<a id="q2"></a>
### Q2 AIが金額を決めるのか。責任は誰にあるのか

**ひとことで:** 金額はAIではなく、御社の単価表にもとづいてプログラムが計算します。最終的な判断と送信は御社の担当者が行います。

**補足**
- 役割分担は「**読み取りと文章はAI、計算と判定はプログラム、最終判断は人**」です。

  | 処理 | 担当 |
  |---|---|
  | 図面・メールからの項目の読み取り、確認メールの文案 | AI |
  | 必須項目の不足チェック、金額の計算(材料費・加工費・段取り費・外注費・管理費・利益) | プログラム(同じ入力なら同じ金額) |
  | 工程ごとの工数の案 | AI(似た過去案件の実績を根拠として示す。根拠のない数値は採用しない) |
  | 工数・利益率の修正、承認、送信 | 人 |

- AIに利益率や値引きは決めさせません。価格の判断は経営判断だからです。
- 見積アシストの出力は判断のための参考情報であり、その位置づけは契約と画面に明記します。

**根拠:** use-cases.md 5.2(設計の原則)、5.5(やらないこと)、5.9(AIガバナンス [S13])

<a id="q3"></a>
### Q3 どのくらい正確なのか(精度は何%か)

**ひとことで:** 御社の図面でどのくらい正確に読めるかは、PoC(試験導入)で項目ごとに測ってお見せします。測る前に数字はお約束しません。

**補足**
- PoCでは、御社の過去の見積30〜50件について、項目別の正解率、「確からしさが高いのに間違っていた項目」の数、確認事項の検出率、類似検索の的中率を測ります([poc-plan.md](poc-plan.md) 4章)。
- 合格ライン(下回ったら本導入しない基準)は、結果を見る前に御社と一緒に決めます。
- 研究では、汎用の大規模なAIが図面の公差の読み取りで専用の小型モデルに劣った例も報告されています [S38]。そのため対象を「文字情報のあるPDFと鮮明なスキャン」に絞り、精度の低い項目は人が入力する欄に回します。

> **社内メモ:** 現行版(MVP)のデモは、AIを使わずにサンプル図面の固定の読み取り結果を表示する「デモモード」です。実際のClaude APIでの正解率・処理時間・費用はまだ計測していません(apps/quote-assist/README.md「制約・未実装」)。デモ画面を見せるときは毎回「デモ用の固定結果」と伝えます。

**根拠:** use-cases.md 5.9(図面読み取りの精度 [S38])、poc-plan.md 4章・6章

<a id="q4"></a>
### Q4 ChatGPTなどに図面を見せれば同じではないか

**ひとことで:** 汎用のAIは図面を読んでもっともらしい金額を返せますが、御社の単価表や過去の実績にもとづいた計算はできず、金額の根拠を示せません。見積アシストは「御社のやり方で計算した、根拠つきの見積案」を作る仕組みです。

**補足**

| 比べる相手 | 見積アシストとの違い |
|---|---|
| 汎用のAIチャット | 自社の単価表・過去実績での計算ができない。承認・CRM登録・修正の記録といった業務の流れに組み込まれていない |
| 社内文書の検索AI | 返すのは「文書」。見積アシストは、過去案件のデータと図面を組み合わせて「見積」という成果物を作る |
| 図面検索のソフト | 図面を探すところまでが中心。見積アシストは受付から確認事項・見積根拠・承認・CRM登録・修正の記録まで扱う(受注・失注結果の記録は次の段階で対応予定。すでにお使いなら連携を検討。Q12) |

- 各金額に「どの単価表・どの過去案件・図面のどこ」を示すので、価格交渉の資料にも使えます。

**根拠:** use-cases.md 6章(差別化)

## 2. 図面の機密と保存場所

<a id="q5"></a>
### Q5 お客様(発注者)から預かった図面をAIに入れてよいのか

**ひとことで:** 御社とお客様の秘密保持契約(NDA)の内容によります。導入前に一緒に確認し、外部のクラウドやAIでの利用が認められていない図面、判断できない図面は対象から外します。

**補足**
- NDAで受け取った技術データを外部のAIに入力すると、契約違反になるおそれがあると指摘されています [S14]。
- 確認の手順を導入の進め方に組み込んでいます(聞き取りシート I章、PoC計画書 9章)。
- 必要なら、AIの処理内容と保存場所を書面にまとめ、御社からお客様に説明する材料としてお渡しします【書面の様式は要作成】。

**根拠:** use-cases.md 2.6・5.9 [S14]、[hearing-sheet.md](hearing-sheet.md) I章、poc-plan.md 9章

<a id="q6"></a>
### Q6 図面はどこに保存され、誰が見られるのか

**ひとことで:** 図面は当社が管理する保存場所【保存先:例 国内リージョンのクラウドストレージ】に保存し、見られるのは御社の利用者と当社の担当者だけにします。御社のクラウド(国内リージョン)に置く専用環境は、オプションとして用意する予定です(時期・費用は【要確認】)。

**補足**
- AIには図面を処理の依頼の中で送り、AI側にファイルを保管する機能は使いません。
- 記録(ログ)には処理時間・処理量・エラーの種類だけを残し、図面の内容・メール本文・金額・お客様の名前は残しません。
- 複数の会社で共用する形では、会社ごとに保存先を分けます。
- PoCで本導入しない場合は、お預かりしたデータを【○日以内】に削除し、書面でご報告します。

> **社内メモ:** 現行版(MVP)には**認証・権限管理がありません**(手元・デモ用)。お客様の実データを預かる前に、保存先・アクセス制限・認証(少なくともBasic認証)を用意すること。保存期間の設定も未実装です。

**根拠:** quote-assist-design.md 6章・7章、poc-plan.md 9章

<a id="q7"></a>
### Q7 AIの学習に使われたり、他社に漏れたりしないか

**ひとことで:** 使っているAI(Anthropic社のClaude)の商用APIでは、送ったデータは標準ではAIの学習に使われないと公表されています。また、御社のデータを他のお客様の検索や評価に使うことはありません。

**補足**
- AIの会社側での保存期間は、同社の規約に従います。公表内容は改定されることがあるため、提供の前に最新の規約で確認してお伝えします。データを保存しない契約(ZDR)は個別の合意が必要です。
- 「絶対に漏れない」とは言えません。そのため、保存場所・処理の経路・記録の扱いを書面で説明し、万一のときの連絡手順を契約で決めます(poc-plan.md 9章)。

**根拠:** Anthropic Privacy Center「Is my data used for model training?」(学習に使わない)・「How long do you store my organization's data?」(保存期間。日数は提供前に原典で確認)、quote-assist-design.md 7章。末尾の「根拠・出典」を参照

## 3. 国内での処理

<a id="q8"></a>
### Q8 国内で処理できるか

**ひとことで:** 標準の構成では、AIの処理場所を国内に限定していません。国内での処理が必要な場合は、Amazon Bedrock の国内(東京・大阪)の処理経路を使う構成を、専用環境のオプションとして用意する予定です。

**補足**
- 国内の処理経路を使うと、AIの利用料は約10%高くなります [S34]。
- 図面の保存場所を国内リージョンのクラウドにする形も、専用環境のオプションとして用意する予定です(現時点では未実装)。

> **社内メモ:** 国内処理(Bedrock)は設計上の差し替え点として用意しているだけで、**現行版では未実装**です(quote-assist-design.md 6章「次段階の候補」)。「今すぐ使える」とは言わず、対応時期と費用は【要確認】として持ち帰ります。

**根拠:** use-cases.md 5.9 [S34]、quote-assist-design.md 6章

## 4. 既存システムとの関係

<a id="q9"></a>
### Q9 今のExcel見積・マクロはどうなるのか

**ひとことで:** 捨てる必要はありません。既存の見積マクロは、当社の「Excelマクロ・Accessの中身を調べるツール」(社内名:棚卸しツール)で中身を洗い出し、計算の考え方を見積アシストの単価表・見積ルールに移す材料にします。

**補足**
- このツールは、シートの構成、マクロ(VBA)の処理と呼び出し関係、数式の件数と代表例、参照している他のファイルやデータベース、ボタンとマクロの対応を抜き出して仕様書にまとめます。対応形式は .xlsm / .xlsx / .xlsb / .xls / .accdb / .mdb です(形式によって抜き出せる範囲が違います)。
- 単価や係数がマクロの中に書かれていれば、マクロのソースから計算の考え方を読み取れます。シートのセルに入った単価表そのものは、ファイルを見ながら聞き取りで確認します。
- セルの値(データ本体)は読み取りません。パスワードは伏せた状態で記録します。
- 仕様書の文章をAIに書かせる場合はマクロのソースコードが外部のAIに送られるため、事前に許可をいただきます。AIを使わずに解析することもできます。
- 「作った人がいない」「中身が分からない」マクロの見える化そのものにも価値があります。

> **社内メモ:** 現行版の見積書はHTMLのプレビュー(ブラウザの印刷でPDF保存)で、**Excelでの出力は未対応**です。Excelの見積書の様式を使い続けたいお客様には、対応方法を【要確認】として持ち帰ります。

**根拠:** use-cases.md 5.3・5.4、hearing-sheet.md F章、apps/inventory/README.md

<a id="q10"></a>
### Q10 Salesforceがないと使えないのか

**ひとことで:** Salesforceがなくても、見積アシストの専用画面で使えます。Salesforceをお使いなら、承認した見積を商談・見積として登録できます。

**補足**
- Salesforceと連携するには、API(外部システムとの接続の仕組み)が使えるエディションが必要です。Enterprise Edition以上では標準で使え、Professional Editionでは追加の契約が必要です [S30]。見積(Quote)機能の有効化も必要です。
- 当社の担当者はSalesforceの初期導入・運用支援を本業としています。今の運用(商談のフェーズ、レポート)に合わせて組み込み、使われていない機能の見直しもご相談いただけます。

> **社内メモ:** 現行版のSalesforce連携は、商談+見積の一方向の登録です。モックでの動作と単体テストのみで、**実際の組織への接続は未検証**です。見積品目(QuoteLineItem)は作らず、明細は見積の説明欄に入れます。PoCで御社の検証環境(Sandbox)を使って確認する、と答えます。

**根拠:** use-cases.md 2.6 [S30]・5.3、quote-assist-design.md 6章、apps/quote-assist/README.md

<a id="q11"></a>
### Q11 生産管理・販売管理のシステムを入れ替える必要があるか

**ひとことで:** 入れ替えは不要です。見積アシストは今のシステムの横で動き、必要なデータだけを受け取ります。

**補足**
- 生産管理・販売管理のデータベース(SQL Server・Accessなど)からは、読み取り専用の形で実績工数・実績原価を取り込む連携ができます(オプション)。当社はC#/SQLでの基幹システムの開発・連携も行っています。
- 見積と実績のずれ(赤字案件)を分析できるようになり、工数の案の精度向上にも使えます。
- kintoneとの連携は次の段階で対応する予定です。

**根拠:** use-cases.md 5.3(外部システムとの連携)、5.4(データ整備度のレベル3)

<a id="q12"></a>
### Q12 図面検索のソフト・サービスをすでに使っている

**ひとことで:** 置き換えるのではなく、連携を考えます。図面検索で見つけた結果を受け取り、その先の確認事項・見積根拠・CRM登録の流れで使う形です。

**補足**
- 見積アシストは図面の形で探す機能(3D形状の類似検索)を持っていません。そこは既存のサービスの得意分野です。
- 連携は次の段階の対応で、製品ごとに個別の確認が必要です【要確認】。

**根拠:** use-cases.md 5.3、5.5(3D形状の類似検索はやらない)、6章

<a id="q13"></a>
### Q13 紙・FAX・手書き・3Dの図面でも使えるか

**ひとことで:** 対象は2D図面のPDF(文字情報のあるPDFと、鮮明なスキャン)です。紙の図面はスキャンすれば対象になりますが、不鮮明なものや手書きの修正が多いものは読み取りが難しくなります。3Dデータの形状解析は対象外です。

**補足**
- スキャンした図面をどこまで読めるかは、PoCで御社の図面で測ってから対象にするかを決めます。
- 紙図面のデジタル化(スキャンと整理)はオプションでお手伝いできます。全量ではなく、リピート品と売上の多いお客様の図面から順に進めます。
- 装置一式・組立品(多階層の部品表)の見積も、現時点では対象外です。

**根拠:** use-cases.md 5.4・5.5・5.9、quote-assist-design.md 9章

## 5. 費用対効果

<a id="q14"></a>
### Q14 費用に見合うのか

**ひとことで:** 引き合いの件数と、1件あたりに減らせる時間で決まります。まず無料診断で今の件数と時間を確かめ、PoCで実測した値で試算し直してから、本導入するかを判断していただきます。

**補足**
- 試算式:

  ```
  月の削減時間 = 月の引き合い件数 × 1件あたりの削減時間 ÷ 60
  月の削減額   = 月の削減時間 × 時間単価
  ```

- 1件あたりの作業時間は、図面1〜3枚・単品〜小ロットの見積で「現状65〜125分 → 導入後15〜30分」という**仮説**です(公的な統計はありません)。試算ではその中から控えめに60分の削減を置きます。
- 例:月120件 × 60分 = 120時間/月。時間単価3,000円で月36万円相当。効果が半分でも月18万円相当で、月額の仮説(5〜10万円)を上回ります。
- ただし、試験導入と初期導入の費用(合計130〜300万円の目安)を取り戻すには、月120件で約4〜20か月、月60件で約10〜143か月かかる試算です(削減30〜60分/件、価格の下限〜中央値で計算)。**月60件未満では、作業時間の削減だけで回収するのは難しい試算**なので、無料診断で件数をうかがい、見合わない場合はそうお伝えします。
- 金額換算は「その時間を別の仕事に回せる」という意味で、人件費が直接減るとは限りません。
- 回答が速くなることによる受注の増加や、赤字案件の早期発見は、事前に金額にしにくいため試算に入れず、導入後にKPI(回答日数、受注率、見積と実績の差)で追います。

> **社内メモ:** 社内試算([pricing.md](pricing.md) 4.3)では、引き合いが**月60件未満**だと、作業時間の削減だけで初期費用を回収するのは難しくなります。件数の少ないお客様には無理に勧めず、Q22のとおり答えます。

**根拠:** use-cases.md 5.1・5.7、pricing.md 4章

<a id="q15"></a>
### Q15 導入実績はあるのか。効果は保証されるのか

**ひとことで:** 見積アシストはまだ導入実績のない新しいサービスです。そのため、御社の実際のデータで効果を測るPoCから始め、結果を見て本導入するかを決めていただく進め方にしています。効果の保証はしていません。

**補足**
- デモでお見せしている会社(しらかば精工)は架空で、画面の数値も合成データです。「想定事例(デモシナリオ)」としてご紹介しています([case-study-demo.md](case-study-demo.md))。
- PoCの合格ラインは結果を見る前に一緒に決め、満たさなければ本導入をお勧めしません([poc-plan.md](poc-plan.md) 6章・10章)。
- 当社の担当者のSalesforce導入・運用支援の実績:【○社・○年】

**根拠:** pricing.md 1章(導入実績はまだない)

<a id="q16"></a>
### Q16 補助金は使えるか

**ひとことで:** 【現時点では対象外です/登録済みです(登録内容)】。補助金の対象・金額は公募要領によって変わり、採択も保証されないため、補助金を前提にしない計画をお勧めしています。

**補足**
- 「デジタル化・AI導入補助金」(旧IT導入補助金)の対象にするには、IT導入支援事業者とツールの登録が必要です [S15]。
- 交付決定の前に契約・支払いをすると対象外になる扱いが一般的です。使う場合は公募要領を確認し、スケジュールに反映します。

> **社内メモ:** 登録していない間は「補助金の対象です」と言わない。「実質○円」のような表現も使わない(pricing.md 6章)。

**根拠:** use-cases.md 2.6 [S15]、pricing.md 6章

<a id="q17"></a>
### Q17 AIの料金が上がったら月額も上がるのか

**ひとことで:** 月額にはAIの利用料が含まれています(上限の件数まで)。AIの料金やモデルが変わったときは、事前に評価用のデータで品質と費用を比べ、影響があればご相談します。

**補足**
- 月額の仮説は「5ユーザー・引き合い200件/月まで、AI利用料込み」です。上限を超えた場合の扱いは【要判断】(従量にするか、上のプランにするか)。
- AIの利用料は1件あたり約140円という推定です(図面2枚と仕様書10ページを想定。実際の値はPoCで計測)。

**根拠:** use-cases.md 5.3(API費用の推定 [S32][S35])・5.7・5.9、pricing.md 2.2・5章

## 6. 現場の受け入れ・運用

<a id="q18"></a>
### Q18 社長やベテランが使ってくれるか。ノウハウを取られないか

**ひとことで:** 見積アシストは「社長の考え方を形にして、社長が確認する」ための道具です。承認する権限は社長(見積担当者)に残り、AIが勝手に見積を出すことはありません。

**補足**
- 最初はリピート品・類似品など、過去の実績が使いやすい見積から使い始めます。
- 社長が工数を直した内容は記録に残ります。月1回の改善ミーティングでその記録を振り返り、単価表や見積ルールに反映していきます。
- 単価の考え方の聞き取り(2時間×2回程度)は、社長の見積ノウハウを文書に残すこと(技能継承)にもなります。まとめた単価表・ルールは御社の資産です。
- 技能継承に苦戦している企業は3社に2社と報じられています [S5]。

**根拠:** use-cases.md 2.2 [S5]・5.4・5.9(現場の受け入れ)

<a id="q19"></a>
### Q19 若手や事務の人でも見積を作れるようになるか

**ひとことで:** 一次案(要件の整理・確認事項・類似案件・計算)までは、社長以外の方でも作りやすくなる想定です。ただし、最終判断は経験のある方が行う前提です。

**補足**
- 「見積担当者以外が一次案を作った割合」をKPIとして測り、属人化がどのくらい減ったかを確かめます。
- 「誰でも見積ができるようになる」とはお約束しません。

**根拠:** use-cases.md 5.8(KPI:属人化)

<a id="q20"></a>
### Q20 準備にどのくらい手間と期間がかかるか

**ひとことで:** 社長・工場長の時間は、PoC(6週間の場合)の間で合計 約15時間前後、本導入では聞き取り2時間×2回程度と単価の確認・テスト利用が目安です。期間は、PoCが4〜6週間、本導入が2〜3か月程度、診断から本番での利用開始まで合計 約5〜7か月を見込んでいます(いずれも目安)。

**補足**

| 段階 | 期間の目安 | 御社にお願いすること |
|---|---|---|
| 無料診断 | 1〜2週間 | 面談、Webの診断への入力 |
| ベースライン計測 | 2〜4週間 | 引き合いごとの作業時間の記録(1件1分程度) |
| PoC | 4〜6週間 | 過去の見積30〜50件のご提供、聞き取り(2時間)、キックオフと報告会(各90分)、週1回30分の定例、正解データと参考にする過去案件の確認、試用10件程度(社長・工場長の時間は合計 約15時間前後。内訳は PoC計画書 7章) |
| 初期導入 | 2〜3か月 | 聞き取り(2時間×2回程度)、単価の確認、テスト利用 |
| 運用 | 月単位 | 月1回1時間程度の改善ミーティング |

- データが紙と社長の記憶だけでも、聞き取りと直近30〜50件のデジタル化から始められます。

**根拠:** use-cases.md 5.4・5.7・5.8、pricing.md 2章(診断と初期導入の期間は筆者の仮置き)、[proposal-template.md](proposal-template.md) 6章

## 7. ベンダーロックイン

<a id="q21"></a>
### Q21 やめたらデータはどうなるのか

**ひとことで:** 単価表・見積ルール・過去案件のデータは御社の資産です。やめるときはCSV/Excelでお渡しし、引き継ぎの手順を契約で決めます。

**補足**
- Salesforceに登録した商談・見積は、御社のSalesforceにそのまま残ります。
- AIの処理先は差し替えられる設計にしています(AnthropicのAPIを直接使う形/Amazon Bedrock経由など)。将来は、中核の機能を他のAIツールからも呼び出せる共通の形式(MCP)で切り出す構想です(現時点では未実装)。

> **社内メモ:** 現行版には**CSV/Excelでの書き出し機能がまだありません**(単価表・過去案件は一般的なテキスト形式のJSONファイルで保持)。書き出しは提供開始までに用意すること【要実装・要確認】。終了時の引き継ぎ手順の契約条項は【要判断】。

**根拠:** use-cases.md 5.3(MCPサーバー化)・5.9(ベンダーロックイン)、quote-assist-design.md 6章、proposal-template.md 10章

## 8. 会社の規模・当社について

<a id="q22"></a>
### Q22 うちのような小さい会社でも使えるか

**ひとことで:** 従業員が少なくても、見積が社長1人に集中している会社は対象です。ただし、費用に見合うかは引き合いの件数で大きく変わるため、まず無料診断で件数と時間を確かめ、見合わない場合はそうお伝えします。

**補足**
- IT担当の方がいなくても、設定・データの取込・連携は当社が行います。Salesforceがなくても使えます(Q10)。
- データが紙だけでも始められます(Q20)。
- 件数が少ない会社向けに、範囲を絞った低価格のプランを検討しています【要判断】。

> **社内メモ:** 社内試算(pricing.md 4.3、時間単価3,000円)では、月30件・削減30分/件だと削減額(月4.5万円)が月額の仮説を下回ります。件数の少ない会社に「元が取れます」とは言わないこと。

**根拠:** pricing.md 4.3・8章(判断事項4)

<a id="q23"></a>
### Q23 設立したばかりの会社で大丈夫か

**ひとことで:** おっしゃるとおり、当社は設立間もない会社です。そのため、小さく始めて結果で判断していただけるPoCから進め、データはいつでも御社にお返しできる形にしています。

**補足**
- 担当者は、Salesforceの初期導入・運用支援とKPI分析・改善提案を本業として【○年・○社】担当しています。基幹システムの開発・連携(C#/SQL)も行っています。
- 単価表・見積ルール・過去データは御社の資産として、いつでもお渡しします(Q21)。終了時の引き継ぎ手順を契約に定めます【要判断】。

**根拠:** proposal-template.md 10章(当社の継続性)

<a id="q24"></a>
### Q24 製造業の見積や現場を分かっているのか

**ひとことで:** 見積の考え方そのものは、社長・工場長が一番よくご存じです。当社の役割は、その考え方を聞き取って単価表と見積ルールの形にし、プログラムで同じように計算できるようにすることと、効果を数字で確かめることです。【製造業の支援経験があれば:製造業のお客様の支援○社】

**補足**
- 聞き取りでは、実際の見積を1〜2件一緒に見ながら、例外のルールや経験則をうかがいます(聞き取りシート)。
- 作った単価表・ルールは、社長・工場長に確認していただいてから使います。最初はリピート品・類似品から使い始めます。
- 分からない加工・工程の話は、推測で決めずに確認します。

> **社内メモ:** 製造業の現場経験がない場合は、知っているふりをしない。「教えていただきながら形にする」姿勢を伝える。担当者の経歴は one-pager の「担当者」欄と同じ内容にそろえる。

**根拠:** hearing-sheet.md(聞き取りのコツ)、use-cases.md 5.4・5.9(現場の受け入れ)

## 9. 言い方の注意(社内メモ)

| 避ける言い方 | 代わりの言い方 | 理由 |
|---|---|---|
| 「見積時間が必ず○分短くなります」 | 「仮説では1件65〜125分が15〜30分です。御社の値はPoCで測ります」 | 効果は仮説で、導入実績はまだない(use-cases.md 5.1) |
| 「完全自動で見積が出ます」 | 「見積の下準備をAIとプログラムが行い、判断と送信は人が行います」 | 自動送信・AIによる値付けはしない設計(use-cases.md 5.5) |
| 「精度は99%です」「間違えません」 | 「AIは間違えることがあります。怪しい項目は目立たせ、未確認のまま承認するには確認のチェックが必要で、そのことも記録に残ります」 | 実際の図面での精度は未計測 |
| 「導入事例があります」 | 「架空の会社での想定事例(デモシナリオ)をお見せします」 | 実在の導入実績はない |
| 「絶対に漏れません」 | 「保存場所・処理の経路・記録の扱いを書面でご説明します」 | 断言できる性質のものではない |
| 「国内で処理しています」 | 「国内での処理は専用環境のオプションとして用意する予定です」 | 標準の構成は国内に限定していない。国内処理は未実装 |
| 「補助金で実質○円です」 | 「補助金は公募要領で対象かを確認します。採択は保証されません」 | 登録が前提で、採択も保証されない(pricing.md 6章) |
| 「使うほどAIが学習して賢くなります」 | 「直した記録を月1回振り返り、単価表やルールに反映します」 | 自動で学習する仕組みはない |
| 「○○社の製品より優れています」 | 「扱う範囲が違います(図面検索までか、見積と記録までか)」 | 他社を悪く言わない。範囲・時点・条件が違う(pricing.md 3章) |
| 「Salesforceにすぐつながります」 | 「御社の検証環境で接続を確かめてから本番に登録します」 | 実際の組織への接続は未検証 |
