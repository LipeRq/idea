- 対象:中小〜中堅の部品加工業(従業員20〜100名程度)の社長・工場長・営業責任者
- 話す人:【自社名】 【担当者名】
- もとにした資料:[use-cases.md](../use-cases.md) 5.6(デモシナリオ)、5.7(価格の仮説)、5.8(KPI)、5.9(リスク)、6章(差別化)/[quote-assist-design.md](../quote-assist-design.md)/[apps/quote-assist/README.md](../../../apps/quote-assist/README.md)
- 画面:[screens/](screens/)(`npm run demo:record` で自動作成。1280×800、ライトモード)
- 録画:`apps/quote-assist/demo-output/quote-assist-demo.webm`(同じコマンドで作成。リポジトリには入れない)

> **このデモについて(必ず守ること)**
> - 画面に出る会社(株式会社しらかば精工、ミナモト装置工業など)・人物・図面・数字は**すべて架空のデモデータ**です。実在の企業とは関係ありません。デモの冒頭で必ずそう伝えます。
> - この流れは**想定事例(デモシナリオ)**です。導入事例ではありません。まだ導入実績はありません。
> - 画面は「デモモード」で動かします。AI(Claude)は使わず、AIが返すのと同じ形の**決まった読み取り結果**を表示します。Salesforceへの登録も**モック(練習用の接続)**で、実際のSalesforceには送りません。
> - 作業時間の短縮や価格は、すべて**仮説・試算**です。数字を出すときは「仮説です」「御社の数字で測り直します」と添えます(根拠は本文に記載)。
> - 「必ず」「完全自動」「100%」などの言い方はしません。**AIは誤ることがあり、最終判断と送信は人が行う設計**であることを伝えます。

## 4. 場面ごとの台本

「操作」は画面のボタン名どおりに書いています。「話すこと」はセリフの例です。そのまま読む必要はありません。相手の業種や規模に合わせて言い換えてください。

### デモの前置き(5分の外。10秒)

> 「これから5分ほど、実際の画面をお見せします。出てくる会社や図面、数字は、説明のために作った**架空のもの**です。今日は練習用の設定で動かしているので、AIの読み取り結果も決まったものを表示します。」

### 場面1 見積待ち一覧(0:00〜0:30)

**画面**:見積待ち一覧(`/`)→ [01-dashboard.png](screens/01-dashboard.png)、[02-backlog.png](screens/02-backlog.png)

**操作**
1. 一覧の画面から始める(右上に「デモモード」「連携先:Salesforce(モック)」と出ていることを確認)。
2. 上の4つの数字を順に指す:見積待ち **12件**(うち8件が社長・工場長の確認待ち)、平均回答日数 **3.3日**、見積受注率 **53%**、実績が見積を超えた案件 **21%**。
3. 下へスクロールし、「見積待ち(デモ用の架空データ)」の表で、オレンジ色の「社長・工場長の確認待ち」を指す。
4. 上に戻り、「新しい引き合いを登録」を押す。

**話すこと**
> 「架空の部品加工会社、しらかば精工です。従業員45名で、見積は社長と工場長の2人が作っている、という設定です。いま見積待ちが12件あって、そのうち8件が社長か工場長の確認待ち。回答までは平均3.3日かかっています。それから、実際にかかった時間が見積を15%以上超えた案件が2割ほどあります。御社でも、見積が特定の方に集中していませんか。」

**補足**:上の4つの数字は、架空の過去案件200件から計算した値です(導入前の状態の例)。

**操作**

### 場面3 抽出結果(0:45〜1:25)

**画面**:抽出結果・確認事項(`/inquiries/[id]`)→ [04-extraction-summary.png](screens/04-extraction-summary.png)、[05-extraction-fields.png](screens/05-extraction-fields.png)

**操作**
1. 上の「引き合いの要約」(1文の要約、図面、形状特徴、注記)を見せる。
2. 下へスクロールして「抽出結果」の表を出す。
3. **材質「SUS304」**の行で、根拠の「MS-24017_C_1.pdf p.1 表題欄の材質欄」を指す。
4. **数量「50個」**(図面の数量欄とメールの両方が根拠)、**表面処理「無電解ニッケルめっき」**、**最小公差「±0.01 mm」**を指す。
5. 下の方の**熱処理**の行の「不足」「確信度 低」を指す。
6. (時間があれば)根拠の図面名のリンクを押すと、その図面PDFが開くことを見せる。

**話すこと**
> 「登録すると、AIが図面とメールから、材質、数量、表面処理、公差などを読み取って一覧にします。大事なのは、それぞれ**図面やメールのどこに書いてあったか**を一緒に出すことです。材質は図面の表題欄から、数量は図面とメールの両方から読んでいます。AIは読み間違えることがあるので、確からしさが低いものや、書いていないものは『不足』『要確認』と目立たせて、人が確かめやすくしています。」

**補足**:今日の画面はデモモードのため、AIは使わず、AIと同じ形の決まった結果を出しています(画面上部にも表示されます)。図面の上に印を付ける表示はなく、根拠は「ファイル名・ページ・位置の説明・原文の引用」で示します。

### 場面5 類似案件・過去案件の詳細(1:45〜2:35)

**画面**:類似案件(`/inquiries/[id]/similar`)→ [07-similar.png](screens/07-similar.png)、[08-similar-more.png](screens/08-similar-more.png)/過去案件の詳細(`/cases/[id]`)→ [09-past-case.png](screens/09-past-case.png)

**操作**
1. 「類似 1 センサブラケット MS-24017 Rev.B」(スコア98.9)を見せ、似ている理由の「同じ図番の旧版(Rev.B)」を指す。
2. オレンジ色の警告2つを指す:「見積工数1.2時間に対し実績1.6時間(1個あたり、+33%)。赤字の可能性」「不具合:寸法不良(めっき後)」。
3. 下へスクロールして類似2・3を見せる(同じ材質SUS304・近い大きさ。類似3には「失注:価格(他社より高い)」)。
4. 類似1の品名のリンクを押して過去案件の詳細を開き、「工程別の工数(見積と実績)」の表を見せる。
5. ブラウザの「戻る」で類似案件に戻り、一番下の「見積根拠へ進む」を押す。

**話すこと**
> 「次に、過去の案件から似ているものを探します。一番上は、同じ図面の前の版です。前回は1個1.2時間で見積もったのに、実際は1.6時間かかっていて、赤字だった可能性があります。めっきの後に穴の寸法が外れて、手直しした記録もあります。こういうことは社長の頭の中にはあっても、記録から探すのは大変です。**御社の過去の見積と実績を根拠にできる**のが、一般的なAIチャットとの違いです。」

**補足**:過去案件は架空の200件です。実績工数は、御社の生産管理や日報にデータがあれば取り込めるようにします(生産管理DBとの連携は次段階の個別開発。【自社名】はC#/SQLでの基幹システム連携の開発ができる、と伝えてよい)。

### 場面6 見積根拠(2:35〜3:05)

**画面**:見積根拠・修正(`/inquiries/[id]/quote`)→ [10-quote-summary.png](screens/10-quote-summary.png)、[11-quote-lines.png](screens/11-quote-lines.png)

**操作**
1. 上の4つの数字を見せる:見積金額 **800,000円**(税抜)、単価 **16,000円**、1個あたり加工時間、標準リードタイム **10営業日**。
2. オレンジ色の枠「抽出結果に未確認の項目が2件あります」を指す。
3. 下へスクロールして「見積明細(根拠つき)」を出し、材料費の行の計算式「1.804kg × 50個 × 750円/kg」を指す。
4. 出典の列の「単価表(材料)」「単価表(チャージ)」「Q-2025-0185」などのリンクを指す。

**話すこと**
> 「ここが見積の根拠です。**金額はAIに決めさせていません。**御社の単価表と工数から、プログラムが計算します。材料費は重さかける数量かける材料単価、加工費は時間かけるチャージ、と1行ずつ式が出ていて、電卓で検算できます。どの単価表、どの過去案件を使ったかもリンクで分かるので、お客様との価格の話し合いでも根拠を説明しやすくなります。」

### 場面7 工数の修正と再計算・単価表(3:05〜3:40)

**画面**:同じ画面の「工程別の工数」→ [12-quote-edit.png](screens/12-quote-edit.png)、[13-quote-recalculated.png](screens/13-quote-recalculated.png)/単価表(`/rates`)→ [14-rates.png](screens/14-rates.png)

**操作**
1. 上へスクロールして「工程別の工数」を出し、出典の欄の「Q-2025-0185(実績1.35h)」(旧版の実績)を指してから、**マシニング加工の「1個あたり(h)」を 1.15 から 1.35 に打ち直す**(旧版の実績に合わせる。1個あたりの合計は1.35時間 → 1.55時間)。
2. 出典に「人が修正」が付き、見積明細の「加工費(マシニング加工)」が 1.35h の式になり、合計が **892,500円**(単価17,850円)に変わるのを見せる。
3. 「修正を保存」を押す。
4. 「加工費(マシニング加工)」の出典の「単価表(チャージ)」を押して単価表を開く。見せたらブラウザの「戻る」で見積根拠に戻る。

**話すこと**
> 「工数の案は、似た過去案件の実績から出していて、マシニングは1.15時間です。でも前回の旧版は、実績で1.35時間かかって赤字だった可能性があります。社長が『今回は実績に合わせて1.35時間で見ておこう』と判断したら、ここを直すだけです。すぐに計算し直されて、80万円が89万2,500円になりました。どこをどう直したかも記録に残ります。」

**補足**:デモモードの工数案は「類似実績から計算」(似た案件の実績工数を似ている度合いで加重平均した値。AIは未使用)です。APIキーを設定すると、AIが類似案件を根拠として示したうえで工数案を出します(根拠のない案は使わない設計)。

### 場面9 見積書・回答メール(3:55〜4:10)

**画面**:見積書・回答メール(`/inquiries/[id]/document`)→ [16-document.png](screens/16-document.png)、[17-reply-email.png](screens/17-reply-email.png)

**操作**
1. 見積書のプレビューを見せる(見積番号、数量別単価(参考)、備考の前提条件)。
2. 下へスクロールして「回答メールの案」を見せる(確認事項2件が入っている)。
3. 上に戻り、「Salesforceに登録する」を押す。

**話すこと**
> 「ここまで社長がしたのは、根拠を見て1か所直し、承認しただけです。承認すると、見積書と、確認事項入りの回答メールの案ができます。送るのは担当の方です。」

**補足**:見積書はブラウザの「印刷・PDFで保存」でPDFにします(Excelでの出力はまだありません)。

### 場面10 Salesforce登録(4:10〜4:35)

**画面**:Salesforce登録(`/inquiries/[id]/crm`)→ [18-crm-before.png](screens/18-crm-before.png)、[19-crm-registered.png](screens/19-crm-registered.png)/Salesforce(モック)(`/crm-mock`)→ [20-crm-mock.png](screens/20-crm-mock.png)

**操作**
1. 「Salesforceへの登録(商談+見積、一方向)」で、送る内容(商談の名前・フェーズ・金額、見積の明細)を見せる。
2. 「Salesforce(モック)に商談と見積を登録」を押す →「登録しました」と出る。
3. (時間があれば)「登録した商談を開く」でモックの画面を見せ、ブラウザの「戻る」で戻る。

**話すこと**
> 「Salesforceをお使いなら、承認した見積を、そのまま商談と見積として登録できます。今日は練習用の接続です。御社の今の使い方に合わせてつなぐのは、私の本業です。」

(Salesforceを使っていない会社では、この場面を飛ばします。3章「Salesforceを使っていない会社のとき」)

**補足**:本物のSalesforceへの登録の仕組み(API)は作ってありますが、実際の組織につないでの確認はまだです。聞かれたら正直にそう答えます。

### 場面11 計測と修正の記録・一覧(4:35〜5:00)

**画面**:Salesforce登録の画面の下の方 → [21-metrics.png](screens/21-metrics.png)/見積待ち一覧 → [22-dashboard-after.png](screens/22-dashboard-after.png)

**操作**
1. 下へスクロールして「計測(この引き合い)」を見せる(処理時間、AIのトークン数と概算費用、登録から承認まで、工数案の採用率)。
2. 「修正の記録」で、マシニング加工 1.15 → 1.2、未確認のまま進めた項目、承認者が残っていることを見せる。
3. 上のメニューの「見積待ち一覧」を押し、「見積アシストで処理した引き合い」に今の1件が「CRM登録済み」で並んでいるのを見せる。

**話すこと**
> 「1件ごとに、処理の時間、AIの費用、人が直した内容が残ります。今日は練習用なので、ミリ秒、0円と出ていますが、実際のAIでは1件あたり百数十円ほどかかる見込みです。導入前の数字と比べれば、効果を数字で確かめられます。」

**補足**
- デモモードなので、処理時間はミリ秒、AIの費用は0円と出ます。**実際にAIを使うと時間も費用もかかります**(費用の推定はFAQの「費用」を参照)。「数秒で終わります」とは言わないでください。
- 「登録から承認まで」は、スクリーンショット([21](screens/21-metrics.png))では自動操作で数秒しかかからないため0分、録画では3分前後と出ます。実演では、その日の操作にかかった分数が出ます。
- 導入前後を比べるグラフ(効果ダッシュボード)はまだありません。比較はPoC(試験導入)の報告書で行う、と説明します([poc-plan.md](../sales/poc-plan.md))。

### 締め(5分の外)

> 「今日お見せしたのは架空のデータでの動きです。御社の図面や見積でどのくらい使えるかは、試してみないと分かりません。ですので、まず無料の診断で、今の見積の流れと月の件数、データの状況をうかがいます。費用に見合うかは引き合いの件数で大きく変わるので、見合わないと分かればそうお伝えします。見合いそうなら、試験導入で御社の過去の見積30〜50件を使い、読み取りの正確さと作業時間を御社の数字で測るところから始めることをご提案しています。」

→ 質疑(5章)、聞き取り([hearing-sheet.md](../sales/hearing-sheet.md))へ。

## 5. よくある質問と答え方

答えの例は言い回しの参考です。**分からないことは「確認してお返事します」と答え、その場で約束しない**のが原則です。

### Q1. AIはどのくらい正確に図面を読めるのか。間違えたらどうなるのか(精度)

> 「正直に申し上げると、御社のような実際の図面での正確さは、まだ測っていません。今日の画面も練習用の設定で、決まった結果を出しています。AIは読み間違えることがある前提で作っていて、項目ごとに『図面のどこに書いてあったか』と確からしさを出し、怪しいものや書いていないものは目立たせています。未確認の項目が残っていると、確認のチェックを入れないと承認できず、未確認のまま進めたことも記録に残ります。金額はAIではなくプログラムが計算し、最後に決めて送るのは人です。どの項目をどのくらい正しく読めるかは、試験導入で御社の図面30〜50件を使って、項目ごとに測ります。」

- 根拠:use-cases.md 5.9(誤った見積・図面読み取りの精度)。2024年の研究では、汎用の大規模なAIが図面の公差の読み取りで専用の小さなモデルに劣った例があります [S38]。正確さの低い項目は「人が入力する欄」に回す方針です。
- 対象は文字情報のあるPDFと、鮮明なスキャンです。手書きの修正、かすれたスキャン、3Dデータは苦手・対象外と伝えます。
- 言わないこと:「○%読めます」「ほぼ間違えません」。

### Q2. 図面はお客様から預かった機密情報。外のAIに送って大丈夫か(図面の機密)

> 「大事な点です。まず、御社が図面を受け取っている主なお客様との秘密保持契約で、外部のクラウドやAIを使ってよいかを、導入の前に一緒に確認します。AIには、図面をその都度読み取りの依頼と一緒に送るだけで、AIの会社側にファイルを置いておく機能は使っていません。AIの会社(Anthropic)が公開している説明では、こうした業務での利用データは標準ではAIの学習に使われません。AIの会社側での保存期間は同社の規約に従います(提供の前に最新の規約で確認してお伝えします)。保存しない契約や、国内のデータセンターで処理する方法も、追加の費用で選べるようにする予定です。アプリの記録(ログ)にも、図面の中身や金額、お客様の名前は残しません。」

- 根拠:use-cases.md 5.9 [S14][S34]、quote-assist-design.md 7章、Anthropic Privacy Center「Is my data used for model training?」(https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)。保存期間は公表情報が改定されているため日数を言わない(確認先:https://privacy.claude.com/en/articles/7996866 。2026-10-21時点で、当社の環境からは公式ページを直接開けず、日数は未確認。use-cases.md の S33 は Claude Code のページで、APIの根拠にならない)。データを保存しない契約(ZDR)は個別の合意が必要、国内(東京・大阪)での処理は Amazon Bedrock 経由で料金が約10%高くなります。
- 今の版の注意:**ログイン(認証)や権限の機能はまだありません**。今は手元とデモでの利用が前提で、提供するときにはログインの仕組みを前に置きます。聞かれたら正直に答えます。
- 言わないこと:「絶対に漏れません」「完全に安全です」。

### Q3. 今のExcelの見積表はどうなるのか(既存のExcel見積との関係)

> 「Excelの見積表を捨てていただく必要はありません。Excelに入っている単価、つまり工程ごとのチャージ、材料の単価、外注の単価、管理費の率と、計算の考え方を、見積アシストの『単価表』に移します。マクロで計算している場合は、Excelマクロの中身を調べる当社のツールで計算式を取り出して移せます。過去の見積の台帳は、類似案件を探す材料として取り込みます。最初はExcelと並べて、同じ引き合いを両方で見積もって差を確かめるのがおすすめです。」

- 根拠:use-cases.md 5.3(Excel見積台帳・見積用マクロ)、5.4(データ整備度に応じた進め方)。社長への「見積の考え方」の聞き取りは2時間×2回程度を想定しています(仮説)。
- 今の版でできないこと:見積書のExcel出力(今は印刷・PDF保存)、画面からのExcel台帳の取込(初期導入の作業として【自社名】がデータを作る)。
- 言わないこと:「Excelのマクロはそのまま動きます」。

### Q4. うちはSalesforceを使っていない(Salesforceが無い会社)

> 「Salesforceがなくても使えます。引き合いの登録から、確認事項、類似案件、見積の根拠、見積書と回答メールの案までは、見積アシストだけで動きます。Salesforceへの登録は最後の、使う会社だけの手順です。kintoneやExcelの台帳に登録したい場合は、次の段階で個別に対応を検討します。逆に、これから営業の管理の仕組みを入れたいというご相談であれば、私はSalesforceの導入と運用の支援を本業にしていますので、そちらもご相談いただけます。」

- 根拠:use-cases.md 5.3(連携先:kintoneは次段階)、quote-assist-design.md 6章。
- 計測と修正の記録は、Salesforceがなくても見積アシストの中に残ります。
- 言わないこと:「kintoneにもすぐつなげます」(まだ作っていません)。

### Q5. いくらかかるのか(費用)

> 「価格はまだ検討中の目安です。進め方は、無料の診断で今の状況をうかがい、次に4〜6週間の試験導入で、御社の過去の見積30〜50件を使って正確さと作業時間を測ります。こちらが30〜50万円ほどを考えています。本格的に導入する場合は、単価表の整理やデータの取込、Salesforceとの連携を含めて100〜250万円、月々の利用料が5〜10万円くらいを目安にしています。月々の費用にはAIの利用料も含めます。合うかどうかは、試験導入の結果を見て判断していただけます。初期費用を何か月で取り戻せるかは、御社の引き合いの件数で大きく変わるので、無料の診断で件数と時間をうかがってから試算をお見せします。」

- 根拠:use-cases.md 5.7、[pricing.md](../sales/pricing.md)(7章のお客様向け価格表(案))。**すべて仮説で、販売実績はまだありません。**
- AIの利用料の推定:図面2枚と仕様書10ページで1件約0.9ドル(1ドル150円で約140円)、引き合いが月120件なら約1.7万円(use-cases.md 5.3 の推定。実際の値は未計測)。
- 費用対効果の考え方(試算):`月の削減時間 = 月の引き合い件数 × 1件あたりの削減時間`。例:120件 × 60分 = 120時間、時給3,000円で月36万円相当(use-cases.md 5.7。60分は5.1節の仮説の削減幅35〜110分の中で控えめに置いた値)。**御社の件数と時間で計算し直す**と伝え、例の数字をそのまま約束しません。
- 回収期間の試算(PoC+初期導入費を、月の削減額−月額で割る。価格の下限〜中央値):月120件・削減30〜60分なら約4〜20か月、月60件・削減60分なら約10〜20か月、月60件・削減30分なら約33〜143か月([pricing.md](../sales/pricing.md) 4.3)。**月60件未満では回収が難しい試算**なので、件数が少ない会社には正直にそう伝えます。
- 補助金:デジタル化・AI導入補助金の対象にするには、IT導入支援事業者とツールの登録が必要です [S15]。【登録状況を記入】。登録していない段階では「対象になるとはお約束できません」と答えます。

## 7. デモが止まったときの対処

まず落ち着いて「少々お待ちください」と一言添え、**30秒で直らなければ予備の録画かスクリーンショットに切り替えて**続けます。デモが止まったこと自体は、正直に伝えて構いません。

| 症状 | その場の対処 | つなぎの一言の例 |
|---|---|---|
| 画面が真っ白・エラーの表示が出た | ブラウザの再読み込み(F5)。直らなければ上のメニューの「見積待ち一覧」から、登録済みの引き合いを開き直す(登録した内容は保存されている) | 「画面を読み込み直します」 |
| 「登録して読み取る」を押しても進まない | 図面が2枚入っているか(「追加した図面」の一覧)を確認。だめなら「サンプル1:改訂品(リピート)を読み込む」を押し直してから登録 | 「サンプルを入れ直します」 |
| 抽出結果が全部「不足」になった | サンプル以外のPDFを入れた可能性。一覧に戻り、「新しい引き合いを登録」からサンプル1で登録し直す | 「デモ用の図面ではないものを入れてしまいました。入れ直します」 |
| 類似案件・見積の画面が「まだありません」 | 上部の「1. 抽出結果・確認事項」に戻り、「類似案件を検索して工数案を作る」を押す | — |
| 数字を打ち間違えた | 正しい値(1.35)を打ち直す。元に戻すなら「工数を案に戻す」 | 「元の案にも、ボタン一つで戻せます」 |
| 「この内容で承認して見積書へ」が押せない | 「未確認の項目(2件)を確認したうえで承認する」にチェックが入っているか確認。入力欄に赤い表示(不正な値)がないか確認 | 「確認のチェックを入れないと承認できない作りです」 |
| 承認しようとすると「金額が変わった」などで断られた | 画面を再読み込みして、表示された金額で承認し直す(画面の金額と計算結果が違うと承認しない作り) | 「表示と計算が食い違わないよう、確認が入りました」 |
| Salesforce登録で「登録済み」と出る | 二重登録を防ぐ仕組み。「登録した商談を開く」かメニューの「Salesforce(モック)」で結果を見せる | 「同じ見積を2回登録しないようになっています」 |
| サーバーが止まった・ページに全くつながらない | ターミナルで止まっていないか確認し、6章のコマンドで起動し直す(保存先を変えると一覧は空になる)。「Could not find a production build」と出たら `npm run build` を先に実行 | 「起動し直す間、録画でご覧いただきます」 |
| ポートが使用中と出る | `-p 3501` など別の番号で起動し、そのアドレスを開く | — |
| パソコン・ブラウザが固まった | 予備の録画を再生(チャプターの時刻で場面に飛ぶ)、またはスクリーンショットを順に見せる | 「同じ操作を録画したものでご説明します」 |
| 時間が足りなくなった | 3章の「短縮版」に切り替える。それでも足りなければ、場面8〜11はスクリーンショットで要点だけ見せる | — |
| 想定外の質問で時間が延びた | 「大事なご質問なので、最後にまとめてお答えします」とメモしてデモを続ける | — |

## 8. 録画とスクリーンショットの作り方

`apps/quote-assist` で次のコマンドを実行すると、この台本の場面1〜11どおりに画面を自動で操作して、スクリーンショットと録画を作ります([scripts/record-demo.ts](../../../apps/quote-assist/scripts/record-demo.ts))。

```bash
cd apps/quote-assist
npm run demo:record                      # 本番ビルド → スクリーンショット → 録画(全体で約6分)
npm run demo:record -- --no-build        # プログラムを変えていないとき(ビルドを省く)
npm run demo:record -- --only=screens    # スクリーンショットだけ / --only=video 録画だけ
npm run demo:record -- --pace=1.5        # 録画を1.5倍ゆっくりにする(1より小さくすると短くなる)
npm run demo:record -- --port=3531       # ポートを変える(既定 3530)
```

| 作るもの | 場所 | 内容 |
|---|---|---|
| スクリーンショット | `docs/manufacturing/demo/screens/01-dashboard.png` 〜 `22-dashboard-after.png` | 1280×800、ライトモード。作り直すたびに全部置き換わる |
| 録画 | `apps/quote-assist/demo-output/quote-assist-demo.webm` | 1280×720。画面の下に場面の字幕、マウスの位置とクリックの表示つき。**リポジトリには入れない**(`.gitignore` 済み) |
| チャプター | `apps/quote-assist/demo-output/quote-assist-demo.chapters.txt` | 録画の中で各場面が始まる時刻(±2秒程度) |
| 失敗したとき | `apps/quote-assist/demo-output/failed-*.png`、`failed-video.webm` | 止まった時点の画面と、そこまでの録画 |

- アプリはデモモード(APIキーを使わない・Salesforceはモック)で、引き合いの保存先を一時ディレクトリにして起動します。終わったら消すので、既存の `.data/` は変わりません。
- サンプル1の希望納期(登録日の40日後)が土日に当たる日は、サーバーとブラウザの日付だけを1〜2日前にずらして、平日の納期で撮ります(アプリの日付ロジックは変えません)。画面の発行日・修正の記録の日時も、ずらした日付になります。
- 場面1・6・7で、件数(12件・3.3日・53%・21%・うち8件)と金額(800,000円・892,500円)が台本どおりかを確かめ、違えば止まります。
- 録画は約5分10秒です。3章の時間配分に合わせて進むように、各画面で待ち時間を取っています(字幕を読み、画面を目で追える速さ)。画面の取り込みの都合で、録画は実際の時間より3%ほど長くなり、後半の場面ほど台本の時刻より数秒〜10秒ほど後ろにずれます(例:場面10は台本4:10、録画4:17)。正確な時刻はチャプターのファイルを見てください。
- 録画には音声がありません。予備として流すときは、4章のセリフを話しながら見せます。
- Playwright のブラウザはプリインストールのもの(`/opt/pw-browsers`)を使います。`playwright install` は不要です。

## 9. シナリオと実装の食い違い(use-cases.md 5.6 との差)

5.6 のデモシナリオを、実際の apps/quote-assist の画面と機能に合わせて組み直しました。食い違いと、この台本での扱いを次に残します。

### 9.1 デモの流れ(5.6 の表)

| # | 5.6 の記載 | 実際のアプリ | この台本での扱い |
