# 自分専用の自動化ツール:アイデア出し

- 作成日:2026-10-24
- この文書の使い方:1章だけ読めば、おすすめと「決めてほしいこと」が分かります。2章で自分の面倒な作業を書き出し、3章の候補と見比べて1本目を選びます。

---

## 1. 結論(要約)

**1本目は「毎朝の情報まとめ」がおすすめです。** AI関連の新着(Anthropic のリリースノート・ニュース)と補助金の公募情報を集め、要点を3行ずつにまとめて毎朝届けます。

選んだ理由は3つです。

1. **毎日使うので、効果がすぐ分かる。** 情報収集は毎日少しずつ時間を取られ、まとめて見ないと見落としも出ます。
2. **作りやすい。** 公開ページと RSS を読むだけなので、メールやカレンダーの認証(いちばん手間のかかる部分)が要りません。半日〜1日で使い始められます。
3. **間違っても被害がない。** 読むだけで、何も送信・登録しません。補助金の情報は顧客への提案材料にもなります。

2本目以降の候補は「打ち合わせメモ → 宿題とお礼メールの下書き」「領収書 → 会計ソフトの取り込み用 CSV」です(3章)。
ただし、これは筆者の推測です。**2章に実際の面倒な作業を書き出すと、優先順位が変わることがあります**(そちらを優先します)。

### 決めてほしいこと

| # | 決めること | 筆者の推奨 |
|---|---|---|
| 1 | 1本目に作るもの | 毎朝の情報まとめ(2章の書き出しでもっと面倒な作業が見つかれば、そちら) |
| 2 | 使っているサービス(メール・カレンダー・会計・チャット) | 書き出しのときに教えてほしい。連携の作り方が決まる |
| 3 | 動かす場所 | GitHub Actions の定期実行(PC を付けておかなくてよい)。手元のファイルを扱うものは自分の PC で |
| 4 | 結果の受け取り方 | メールかチャット(Slack など)。スマホで読めるもの |

## 2. 面倒な作業の書き出し(記入用)

思いついた順に書いてください。数字はだいたいで構いません。

| 作業 | どのくらいの頻度か | 1回の時間 | 何が面倒か | 材料はどこにあるか | できたものをどこに置くか |
|---|---|---|---|---|---|
| (例)AI関連のニュースを追う | 毎日 | 20分 | あちこちのサイトを見に行く | 各社のブログ・ニュースサイト | 頭の中(メモしていない) |
| | | | | | |
| | | | | | |
| | | | | | |

思い出すための問い:

- 毎朝・毎週・毎月、決まってやっていることは?
- コピーして貼り付けている作業は?(2つのサービスを行き来している作業)
- 同じような文章を何度も書いていないか?(返信・お礼・案内・報告)
- 忘れて困ったこと、後回しにしがちなことは?
- 「これは自分がやらなくてもいいのに」と思う作業は?

月あたりの時間(頻度 × 1回の時間)が大きいものほど効果が大きくなります。
診断ツール(`apps/diagnosis`)で顧客にやっていることを、自分に当てはめる形です。

## 3. アイデアの候補

大きさの目安:**小**=半日〜1日、**中**=2〜3日、**大**=1週間以上(メールやカレンダーなどの認証の設定を含むもの)。
「AI」は Claude API を使うかどうか。使うものは、送る内容(顧客の情報を含むか)を README に書きます。

### A. 情報収集

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| A1 | 毎朝の情報まとめ | AI関連の新着と補助金の公募情報を集め、要点を3行ずつにまとめて毎朝届ける | 小 | 使う |
| A2 | 補助金の新着の見張り | IT導入補助金・ものづくり補助金などの公募・締切を見張り、顧客の業種に関係しそうなものだけ知らせる | 小 | 使う |
| A3 | 顧客企業の動きの見張り | 顧客の Web サイト・プレスリリースの更新を週1回まとめる(面談の話題づくり) | 小 | 使う |

### B. 打ち合わせ・予定

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| B1 | 打ち合わせメモの整理 | メモや文字起こしを貼ると、議事録・決まったこと・宿題(誰が・いつまで)・お礼メールの下書きを作る | 小 | 使う |
| B2 | 面談前の下調べ | 翌日の予定の相手について、会社の概要と過去のやりとりをまとめて前日の夜に届ける | 中〜大 | 使う |
| B3 | 日程調整の文面づくり | カレンダーの空きから候補日時を選び、日程調整のメール文を作る | 大 | 使わない |

### C. メール・連絡

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| C1 | 問い合わせの振り分けと返信の下書き | 未読メールを種類(相談・営業・請求・その他)に分け、返信の下書きを作る。送信は自分で押す | 大 | 使う |
| C2 | 返信漏れの見張り | 「確認して返信します」と書いたまま3日たったメールを、毎朝一覧にする | 大 | 使う |
| C3 | 相談申し込みの事前調査 | 診断ツールから相談申し込みが来たら、会社名から概要を調べて面談前メモを作る | 中 | 使う |

### D. お金・事務

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| D1 | 領収書の読み取り | 写真や PDF をフォルダに入れると、日付・金額・支払先・勘定科目を読み取り、会計ソフト(freee・マネーフォワードなど)の取り込み用 CSV にする | 中 | 使う |
| D2 | 請求書の作成 | 月末に、契約の一覧から請求書の PDF と送付メールの下書きを作る | 中 | 使わない |
| D3 | 入金の突き合わせ | 銀行の明細 CSV と請求の一覧を突き合わせ、未入金を一覧にする | 小 | 使わない |
| D4 | 稼働時間の集計 | カレンダーとコミットの記録から、顧客ごとの作業時間を月ごとに出す | 中 | 使わない |

### E. 資料・報告

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| E1 | 週報・進捗メモの下書き | コミットの記録とカレンダーから「今週やったこと・残っていること」を下書きする(`docs/progress.md` の更新にも使える) | 小 | 使う |
| E2 | 提案書の下書き | ヒアリングのメモから、提案書のひな形(`docs/manufacturing/sales/proposal-template.md`)を埋めた下書きを作る | 中 | 使う |
| E3 | 発信のネタ帳 | 作業の記録から、ブログや SNS に書けそうな話題と下書きを週1回出す | 小 | 使う |

### F. ファイル・開発

| # | ツール | やること | 大きさ | AI |
|---|---|---|---|---|
| F1 | ダウンロードフォルダの整理 | ファイル名を「日付_相手_種類」にそろえ、種類ごとのフォルダに振り分ける | 小 | 一部 |
| F2 | 依存関係の更新のまとめ | Dependabot の更新を、CI が通ったもの・止まっているものに分けて週1回一覧にする | 小 | 使わない |
| F3 | 名刺の読み取り | 名刺の写真から連絡先を読み取り、Salesforce の取引先責任者の登録用データにする(登録は確認してから) | 中 | 使う |

## 4. 選び方

候補ごとに次の3つを見て、合計が高いものから作ります。

| 見るところ | 高い | 低い |
|---|---|---|
| 効果 | 月あたりの時間(頻度 × 1回の時間)が大きい | 月に数分しか使わない |
| 作りやすさ | 公開ページ・手元のファイル・貼り付けだけで動く | メールやカレンダーの認証、会計ソフトの API が要る |
| 被害の小ささ | 読むだけ・下書きを作るだけ | 送信・登録・支払いまで自動でやる |

筆者のおすすめ順(2章の書き出しで入れ替わります):

1. **A1 毎朝の情報まとめ**(A2 を含める):効果・作りやすさ・被害の小ささのすべてが高い
2. **B1 打ち合わせメモの整理**:貼り付けるだけで動く。打ち合わせのたびに 20〜30分ほど減らせる見込み
3. **D1 領収書の読み取り**:月1回でも溜めると重い。画像の読み取りは Claude が得意で、取り込む前に自分で確認できる
4. **E1 週報・進捗メモの下書き**:材料(コミットの記録)がすでにリポジトリにある

メールやカレンダーにつなぐもの(B2・B3・C1・C2)は効果が大きい一方、認証の設定に時間がかかります。
1〜2本作って作り方が固まってから取りかかるのがよいと考えます。

## 5. 作り方の共通方針(案)

- 言語は既存のアプリと同じ TypeScript / Node.js 22。まずはコマンド(CLI)で動かし、画面は必要になってから作る
- 定期実行は GitHub Actions のスケジュール実行。手元のファイルを扱うもの(D1・F1 など)は自分の PC で動かす
- Claude API の構造化出力の検証は `packages/shared` の部品を使う
- 届け先(メール・チャット)は1つの部品にまとめ、どのツールからも同じ方法で送る
- 自分で使っているツールは、顧客への説明の材料にもなる(ただし実データ・個人の情報はポートフォリオに載せない)
