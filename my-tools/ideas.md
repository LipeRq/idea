# 自分専用の自動化ツール:アイデア出し

- 作成日:2026-10-24(同日更新:候補1・2を選択、受け取りは LINE、アイデアを追加)
- この文書の使い方:1章だけ読めば、作る順番と「決めてほしいこと」が分かります。3章が選んだ2つの具体案、5章がアイデアの一覧です。

---

## 1. 結論(要約)

**自分専用の LINE ボット(LINE 公式アカウント)を1つ作り、すべてのツールの入口と出口にします。**
LINE は普段から開いているので、通知を見落としにくく、スマホから写真や音声入力でそのまま送れます。

作る順番:

1. **毎朝の情報まとめ**(半日〜1日):AI関連の新着と補助金の公募情報を集め、要点をまとめて毎朝 LINE に届けます。こちらから送るだけなので、受信用のサーバーは要りません。
2. **打ち合わせメモの整理**(1〜2日):LINE にメモを送ると、議事録・宿題・お礼メールの下書きを返します。ここで「LINE から受け取る」仕組み(受信用のサーバー)ができます。
3. **LINE に送るだけで片づくもの**を足していく(1本あたり半日ほど):思いつきメモ、あとで読む、領収書、リマインダーなど(5章 G)。1と2で作った送受信の部品をそのまま使えます。

### 決めてほしいこと

| # | 決めること | 筆者の推奨 |
|---|---|---|
| 1 | 使っているのは LINE(個人向け)か LINE WORKS(仕事向けの別サービス)か | LINE の前提で書いています。LINE WORKS なら作り方が変わります |
| 2 | 毎朝の情報まとめで追いたい分野 | AI関連・補助金に加えて、顧客の業種(製造業など)のニュース。天気や予定も一緒に届けるか |
| 3 | 打ち合わせメモをどう残しているか(手書き・スマホのメモ・録音・何もしていない) | 最初は「LINE にテキストで送る(スマホの音声入力で話す)」から。写真(手書き・ホワイトボード)も読める |
| 4 | 顧客の情報を LINE と Claude API に通してよいか | 顧客との秘密保持契約で外部サービスの利用が問題ないか確認する。だめな顧客は社名・人名を伏せて送る |
| 5 | 受信用のサーバーをどこに置くか | 既存のアプリと同じ Vercel(Next.js)。費用と利用条件は作る前に確認する |

## 3. 選んだ2つの具体案

### 3.1 毎朝の情報まとめ

```
毎朝7時(GitHub Actions の定期実行)
  → 情報源から新着を集める(RSS・公開ページ)
  → 前日までに送ったものを除く
  → Claude が重要な順に5件ほど選び、それぞれ3行で要約
  → LINE に1通で届ける(見出し・3行・リンク)
```

- 情報源は設定ファイルに並べ、あとから足し引きできるようにする(案:Anthropic のニュース、国内の AI ニュース、補助金の公募情報、顧客の業種のニュース)
- 補助金は「締切が近いもの」「顧客の業種に合いそうなもの」に印を付ける
- 送るのは1日1通(月30通ほど。LINE の無料プランの範囲。4章)

伸ばし方:

- 気になった記事の番号を LINE で返すと、詳しい要約が返ってくる(2で受信の仕組みができてから)
- 土曜の朝は1週間分の振り返り(大事だったもの3つ)
- 天気・今日の予定・ゴミの日などの身の回りの情報も同じ1通に入れる

### 3.2 打ち合わせメモの整理

```
打ち合わせのあと、LINE のボットにメモを送る(テキスト・写真)
  → 受信用のサーバーが受け取り、Claude で整理する
  → LINE に返す
     ・議事録(要点・決まったこと)
     ・宿題(誰が・何を・いつまで)
     ・次回までに確認すること
     ・お礼メールの下書き(コピーしやすいように別の吹き出し)
```

- メモはスマホの音声入力で話すのがいちばん早い。手書きのメモやホワイトボードは写真で送れば読み取れる
- LINE の音声メッセージ(録音)は、文字起こしの仕組みが別に要るので後回し
- 最初は保存しない(LINE のトークに残るだけ)。顧客の情報なので、リポジトリには入れない。保存先は使ってみてから決める

伸ばし方:

- 宿題の期日の前日に LINE で知らせる
- 次の打ち合わせの前日に、前回の議事録と宿題を LINE に届ける(保存先とカレンダーの連携が要る)
- お礼メールを Gmail などの下書きに入れる、Salesforce の活動履歴に登録する(どちらも確認してから)

## 4. LINE でつなぐときの仕組みと注意

2026年10月時点の公式の情報で確認しました(末尾の参考)。

| 項目 | 内容 | このツールでの扱い |
|---|---|---|
| 送る手段 | LINE Notify は 2025年3月31日に終了。今は LINE 公式アカウントを作り、Messaging API で送る | 自分専用の公式アカウントを1つ作る(友だちは自分だけ) |
| 料金 | 無料のコミュニケーションプランで、こちらから送るメッセージ(プッシュ)が月200通まで。超えると送れない。届いたメッセージへの返信(応答メッセージ)は数に入らない | 毎朝の1通で月30通ほど。打ち合わせメモへの返事は返信なので数に入らない |
| 返信の時間 | 返信は受け取ってから1分以内が目安(公式は、時間制限を前提にしないよう案内している) | AI の処理中は読み込み中のアニメーションを出す。間に合わなかったときだけプッシュで送る |
| 読めるもの | ボットとのトークと、ボットを入れたグループのメッセージだけ。人との個人のトークは読めない | 「ボットに送る・転送する」使い方にする |
| 安全 | ボットは誰でも友だち追加できる | 自分の LINE のユーザー ID からのメッセージだけに反応する。受信時に LINE の署名を検証する |
| 通る場所 | メモの内容は LINE と Claude API を通る | 1章の「決めてほしいこと」4 |

G と H は、3章の2つを作ったあとなら、ほぼ「足すだけ」の大きさです。

## 6. 選び方

候補ごとに次の3つを見て、合計が高いものから作ります。

| 見るところ | 高い | 低い |
|---|---|---|
| 効果 | 月あたりの時間(頻度 × 1回の時間)が大きい | 月に数分しか使わない |
| 作りやすさ | 公開ページ・手元のファイル・LINE に送るだけで動く | メールやカレンダーの認証、会計ソフトの API が要る |
| 被害の小ささ | 読むだけ・下書きを作るだけ | 送信・登録・支払いまで自動でやる |

3章の2つのあとに作るものの、筆者のおすすめ順(2章の書き出しで入れ替わります):

1. **G1 思いつきメモ箱・G2 あとで読む・G3 リマインダー**:どれも半日ほどで、毎日使う
2. **H1 宿題の追いかけ・H3 顧客に伝えたい情報**:選んだ2つの効果をそのまま大きくする
3. **G5 領収書を撮って送る**:月1回でも溜めると重い。取り込む前に自分で確認できる

メールやカレンダーにつなぐもの(B・C・H2)は効果が大きい一方、認証の設定に時間がかかります。
LINE の部品が固まってから取りかかるのがよいと考えます。

## 7. 作り方の共通方針(案)

- 言語は既存のアプリと同じ TypeScript / Node.js 22
- LINE の部品は2つに分け、どのツールからも使う
  - 送る部品:自分の LINE に送る(プッシュ)。毎朝の情報まとめなど、定期実行(GitHub Actions)から呼ぶ
  - 受ける部品:受信用のサーバー(Next.js の API)。署名の検証と「自分だけ」の確認をしてから、メッセージの種類(テキスト・写真・URL)と内容で各ツールに振り分ける
- ツールの切り替えは、まずは AI に内容から判断させ、迷うときはトーク画面の下のボタン(リッチメニュー)で選べるようにする
- Claude API の構造化出力の検証は `packages/shared` の部品を使う
- 自分で使っているツールは、顧客への説明の材料にもなる(ただし実データ・個人の情報はポートフォリオに載せない)
