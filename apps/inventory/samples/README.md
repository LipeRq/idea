# デモ用サンプル(架空の中小企業のマクロ付きブック)

営業デモ・ポートフォリオで使う「作った人が辞めて、誰も中身が分からない」マクロ付きブックのサンプルです。
架空の製造業「株式会社サンプル精工」の社内で使われている想定で、よくある問題を意図的に仕込んでいます。
`output/` には、それぞれを解析して作った標準の仕様書(AI なし)を保存しています。出力例として、そのまま資料に使えます。

- 会社名・人名・サーバー名・パス・メールアドレス・パスワードはすべて架空(ダミー)です。メールアドレスと URL は `example.com` / `example.co.jp` / `example.jp` を使っています。
- ファイルはコードで生成した合成データで、解析ツールに読み込ませるためのものです。VBA はソースだけを持ち(p-code なし)、Excel で開いて動かすことは確認していません。
- VBA の参照設定はテスト用ヘルパー(`test/helpers/ovba.ts`)の固定値(stdole・ADODB・MSForms)のため、DB を使わない見積書作成.xlsm にも ADODB の参照設定が出ます。
- 解析と仕様書の作成には、ブラウザ版と同じ入口(`src/browser.ts` の `analyzeBuffer` / `renderMarkdown`)を使っています。Chromium 上のバンドル(`scripts/build-browser.mjs`)で解析しても `output/` の仕様書と完全に一致することを確認済みです。

## 各サンプルの設定(仕込んだ問題)

### 受注管理.xlsm(受注入力・請求書発行)

作成 2014 年・最終更新 2022 年。シート: メニュー / 受注一覧 / 顧客マスタ / 商品マスタ / 請求書(非表示) / 設定(非表示)。

- **入力画面から Access の受注DBへ直接書き込む**: フォーム `frm受注入力` → `mod受注.受注登録` → `modDB.受注をDBへ書き込み` が ADO で `\\fileserver01\営業部\受注管理\受注DB.accdb` に DELETE / INSERT する。エラー処理はなく、SQL は文字列の連結で組み立てている。
- **ワークシート関数から DB に問い合わせる**: 顧客マスタの D 列の数式 `=顧客の未請求額(A2)` が、セルごとに DB に接続する(ユーザー定義関数)。
- **パスの直書き**: 受注DB(共有フォルダ)、請求書PDFの保存先(`C:\Users\yamada\Desktop\請求書\`)、閉じるときのバックアップ先(`D:\バックアップ\…`)。設定シートに保存先の欄があるのに、コードは使っていない(コメントにだけ書いてある)。
- **起動のきっかけが画面のあちこちにある**: メニューのボタン 3 つ(フォームコントロール 2・図形 1)、受注一覧のダブルクリック、ブックを閉じる前、入力画面のボタン。
- **保守性**: `mod請求書` に Option Explicit がない(宣言していない変数 `i` `n` を使っている)。2019 年まで使っていた `旧_請求書発行` が残っている。請求書の明細は「最大15行」とコメントにあるが、超えたときの確認がない。

### 月次売上集計.xlsm(営業所別の集計・報告)

作成 2016 年・最終更新 2024 年。シート: 集計 / 東京 / 大阪 / 名古屋 / 予算対比 / 作業用(非表示)。

- **コピーして増やした長いプロシージャ**: `月次集計メイン`(241 行)は、営業所ごとにほぼ同じ処理を 3 回コピーしたもの。大阪だけ開始行が違う、名古屋だけ返品の列がずれている、などの違いがコメントで分かる。
- **On Error Resume Next**: 先頭でエラーを無視しているため、営業所のファイルが届いていなくても最後まで進み、「集計が終わりました」と表示される。
- **SendKeys と Shell による画面操作**: ブックを開いた後の確認に Enter を送る。販売管理システム(`C:\HANBAI\HanbaiMenu.exe`)を Shell で起動し、Alt+F → I → ファイル名 → Enter をキー送信して取込メニューを操作する。
- **他ブックへの数式リンク**: 予算対比シートが `\\fileserver01\経営企画\予算\2024年度予算.xlsx`(年度でファイル名が変わる)と、担当者個人のフォルダの `C:\Users\tanaka\Documents\月次\前年実績.xlsx` を参照する。
- **Outlook でのメール送信**、**CSV の書き出し**(`D:\HANBAI\IMPORT\`)。
- **#REF! の名残**: 2023 年に統合した名古屋2課の数式(`=SUM(#REF!)`)と名前定義(`旧名古屋2課`)。
- **保守性**: `mod月次集計` と `mod共通` に Option Explicit がない。

### 在庫引当マクロ.xlsm(在庫取込・自動引当)

作成 2018 年・最終更新 2020 年(作成者=最終更新者。システム担当が 1 人で作り込んだ想定)。VBA プロジェクトは表示用にロックされている。
シート: 在庫一覧 / 受注残 / 引当結果 / 出荷状況 / 棚卸差異 / 接続設定(完全に非表示)。

- **開くと自動で動く**: `Workbook_Open` で倉庫のPC(`Environ("COMPUTERNAME")`)か確かめ、`net use` で共有フォルダに接続 → 在庫取込 → 30 分後の予約。`定時取込` が自分自身を `Application.OnTime` で予約し直し、取り消す処理がない(コメントに「閉じても勝手に開き直す。要調査」)。`Application.OnKey` で Ctrl+Shift+Z に在庫照会の画面を割り当てる。
- **64 ビット版で動かない Declare**: `Sleep`(kernel32)・`GetUserNameA`(advapi32)・`FindWindowA`(user32、宣言だけで未使用)に PtrSafe がない。
- **パスワードの直書き(すべてダミー値)**: 接続文字列の定数(`Password=…`)と、それを別モジュールにコピーした接続文字列、コメント(「DBのパスワードは「…」」)、シート保護(`Unprotect` / `Protect`)、`net use` のパスワード、データ接続(ODBC)の `PWD=…`。仕様書・JSON のどこにも元の値が残らず `****` になることを、生成時に確かめている。
- **IE の自動操作**: 運送会社のサイト(`https://tracking.example.com/…`)を `InternetExplorer.Application` で開いて配送状況を読む。
- **その他の外部依存**: SQL Server(ADO)への SELECT / UPDATE / INSERT、Outlook での発注依頼メール(下書き表示)、ハンディターミナルの CSV 取込(`C:\HANDY\DATA\`、読み込み後に FileCopy / Kill)、ピッキングリストの印刷、`Z:\出荷\` への保存。
- **エラー処理**: 接続のやり直しに `On Error Resume Next` を使い、`On Error GoTo 0` で戻した後は無防備。棚卸差異の DB 反映はトランザクションを使っているがエラー処理がない。
- **隠れた設定**: 接続設定シートは「完全に非表示」(Excel の画面からは再表示できない)。仕入先のメールアドレスや棚番の例外はコードに直接書かれている。

### 見積書作成.xlsm(比較用: 問題の少ないブック)

作成 2021 年・最終更新 2023 年。シート: 見積書 / 単価表 / 見積履歴。

- 処理の中心は数式(144 個。VLOOKUP・掛率・利益率・消費税)で、マクロは採番・PDF保存・履歴記録の補助だけ(コード 54 行)。
- PDF の保存先はブックと同じフォルダからの相対指定(`ThisWorkbook.Path`)で、エラー処理もある。
- 仕込んだ問題は 1 つだけ: シート「見積書」のモジュールに Option Explicit がない。
- ルールで選ぶ移行先の候補は「Excel のまま整理(テーブル・関数・Office スクリプト)」が先頭になる(作り直さなくてよいものも見分けられることを見せるため)。

### AI 版の仕様書で拾われることを期待する手がかり

標準レポート(AI なし)は機械的なルールで検出できるものだけを載せます。次の点はコメントやコードの書き方にだけ表れるため、AI で詳しい仕様書を作ったときに「気になる点」「現場に確認すること」として挙がることを想定して仕込んでいます(AI の出力は実行のたびに変わるため、生成時の確認の対象にはしていません)。

- 受注管理: SQL を文字列の連結で組み立てている、設定シートの保存先を使っていない、請求書の明細が 15 行を超えたときの扱い、セルごとに DB に接続するワークシート関数
- 月次売上集計: 営業所ごとの処理の違い(開始行・返品の列)、区分なしの売上を製品に入れるルール(部長指示)、祝日を考慮しない営業日の計算、年度でファイル名を書き換える運用
- 在庫引当マクロ: OnTime の予約を取り消さない(閉じても開き直す)、接続文字列のコピー、仕入先マスタが無くアドレスを直書き、棚番の例外の直書き、IE でないと動かない

## 再生成の方法

```bash
cd apps/inventory
npm install                           # 初回のみ

npx tsx samples/generate.ts           # .xlsm・output/*.md・manifest.json を作り直す
npx tsx samples/generate.ts --check   # 書き出さずに、保存済みのファイルと一致するか・狙いどおり検出されるかだけを確かめる
npx tsc -p samples/tsconfig.json      # 生成スクリプトの型チェック
```

`generate.ts` は次の順に処理し、どれか 1 つでも狙いどおりでなければ何も書き出さずに終了コード 1 で止まります。

1. `defs/*.ts` の定義から .xlsm を組み立てる(VBA プロジェクトは `test/helpers/ovba.ts` の `buildVbaProjectBin`、cp932)
2. `analyzeBuffer` で解析し、定義に書いた期待値を確かめる
   - 検出されるべきリスク・検出されてはいけないリスク、起動のきっかけの種類、外部依存の種類、移行難易度の目安、移行先候補の先頭
   - ダミーのパスワードが JSON にも仕様書にも残っていないこと
   - 取り出した VBA のソースが元のソース(パスワードを伏せたもの)と 1 文字も違わないこと(cp932 で表せない文字を使っていないかの確認も兼ねる)
   - サンプルごとの個別の確認(DB 書き込みがエラー処理なしとして挙がる、OnTime・OnKey の割り当て先が解決される、など)
3. 標準の仕様書(AI なし)を `output/<名前>.md` に、一覧を `manifest.json` に書き出す

生成結果は毎回同じバイト列になります(zip の更新日時と仕様書の生成日時 `2026-10-20T00:00:00Z` を固定)。解析エンジンを変更したときは `--check` で出力例が変わっていないかを確かめ、意図した変更なら生成し直してください。

サンプルを増やすときは、`defs/` に定義(`SampleDefinition`)を追加し、`generate.ts` の `SAMPLES` に登録します。VBA のソースは `lib/vba.ts` の `vba` タグで書くと、パスの `\` を VBA と同じ表記で書けます。

## manifest.json

画面アプリ(`apps/inventory-web`)などでサンプルを並べるための一覧です。`generate.ts` が `defs/` の文言から作ります。

```json
[{ "file": "受注管理.xlsm", "title": "…", "description": "…", "highlights": ["…", "…"] }]
```

| 項目 | 内容 |
| --- | --- |
| `file` | `samples/` 直下のファイル名(仕様書は `output/` に拡張子を `.md` にした名前で置いている) |
| `title` | 表示用の名前 |
| `description` | どんな業務のファイルか(1〜2 文) |
| `highlights` | 解析で見どころになる点(画面に箇条書きで出す想定) |
