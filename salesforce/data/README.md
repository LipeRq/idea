# 架空データ

`scripts/generate-data.ts` が生成した、しずく茶舗(架空)のデータです。手で書き換えず、変えるときはスクリプトを直して `npm run generate-data` を実行します。
乱数の種(20261103)と基準日(2026年10月31日)を固定しているので、何度実行しても同じ内容になります。
人物・会社・メールアドレス・電話番号はすべて架空です(メールは予約済みのドメイン `example.com` などと `.example` だけを使用)。

日時は UTC(末尾 Z)で書いています。日本時間に直すと 9 時間後です。

## 架空データの特徴

- EC会員 1,200 人のうち、購入したことがある人は 1,046 人、2 回以上購入した人は 483 人
- 初回購入から 90 日以内に 2 回目を買った人の割合(初回が 90 日以上前の人のうち):**30.2%**(KPI「2回目購入率」の現状値として使う)
- ギフト注文の割合:16.7%(お中元 6/15〜7/15、お歳暮 11/20〜12/20 に集中)
- 取引先責任者 88 人のうち、EC会員と同じ人は 23 人(会社のアドレスで EC を使っている人 15 人、個人のアドレスで使っている人 8 人)
- 法人ギフトの商談 140 件のうち、完了 115 件の受注率 55.7%、リピート商談の受注率 87.5%

## 名寄せの期待値(検算用)

Data 360 の ID 解決ルールセットを `../docs/02-data360.md` のとおりに設定すると、統合プロファイルの数は次のようになるはずです。
組織で ID 解決を実行したら、この数と比べて設定を確かめます。

| 元の件数 | 件数 |
|---|---:|
| EC会員 | 1,200 |
| 店舗会員 | 370 |
| 取引先責任者 | 88 |
| リード | 41 |
| **合計** | **1,699** |
| **統合後の人数(期待値)** | **1,462** |

店舗会員 370 人の内訳(生成時に決めた正解):

| 種類 | 人数 | 統合されるか(どのルールで) |
|---|---:|---|
| メールアドレスが同じ(大文字・前後の空白の揺れあり) | 82 | される(メールアドレス) |
| メールなし・氏名と電話番号が同じ(異体字・電話番号の書き方の揺れあり) | 77 | される(氏名+電話番号) |
| アプリで EC会員と連携済み | 30 | される(EC会員ID) |
| 古いメールアドレス・氏名と電話番号が同じ | 21 | される(氏名+電話番号) |
| 店舗だけの会員 | 140 | されない |
| EC会員の家族(同じ姓・同じ電話番号・名が違う) | 20 | **されない**(電話番号だけでは統合しない) |

ルールを変えたときの人数(誤ったルールで何が起きるか):

| ルール | 統合後の人数 | 期待値との差 | 起きること |
|---|---:|---:|---|
| 期待値のルール | 1,462 | 0 | — |
| 異体字を正規化しない | 1,471 | +9 | 同じ人が別人のまま残る(髙橋/高橋、山﨑/山崎 など) |
| 共有アドレス(soumu@ など)もメールで統合する | 1,460 | -2 | 総務部の別の担当者どうしが 1 人になる |
| 氏名を見ずに電話番号だけで統合する | 1,394 | -68 | 同じ電話番号の家族や、同じ会社の代表電話を登録した別々の担当者が 1 人になる |
